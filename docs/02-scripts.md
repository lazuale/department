## PS-01. Принять новую работу

1. Определить, нужен ли отдельный контролируемый результат.
2. Проверить, нет ли Задачи на тот же результат.
3. Если нужна новая Задача — создать её в общем рабочем Проекте.
4. Указать Тип задачи, Процесс и для `Работы` Вид работы.
5. Назначить Ответственного.
6. Поставить Крайний срок, если он известен.
7. Если выполнение начинается сейчас — Этап `В работе`, иначе `Очередь`.

Не создавать Задачу на каждое письмо, файл, звонок или технический шаг.

## PS-02. Зарегистрировать `Запрос`

Отдельный `Запрос` создаётся, если получение документа, данных, материала или подтверждения само требует самостоятельного контроля.

Минимально:

- `Тип задачи = Запрос`;
- Процесс;
- Ответственный;
- Крайний срок получения;
- понятное название результата.

После отправки, если остаётся только ждать, Этап → `Внешнее ожидание`. Для повторного контроля по дате создаётся Активность.

Если получение — обычный шаг внутри уже открытой работы, отдельный `Запрос` не создаётся.

## PS-03. Отложить принятую работу

Если работа принята, но сознательно отложена:

- Этап → `Очередь`;
- Ответственный сохраняется;
- Крайний срок сохраняется;
- при необходимости создаётся Активность на дату возврата.

Короткое переключение на другой вопрос не требует менять Этап.

## PS-04. Внешнее ожидание

1. Сделать всё доступное со своей стороны.
2. Перевести Задачу во `Внешнее ожидание`.
3. В истории общения указать, что конкретно ожидается, если это не очевидно из переписки.
4. Создать Активность, если нужен контроль по дате.
5. Крайний срок Задачи автоматически не переносить.

После снятия причины:

- продолжаем сейчас → `В работе`;
- продолжим позже → `Очередь`.

## PS-05. Внутренняя зависимость

Если Задача не может продолжиться до завершения другой Задачи:

1. создать или найти блокирующую Задачу;
2. указать её в поле `Блокирующие задачи`;
3. не дублировать зависимость текстом;
4. после закрытия блокирующей Задачи продолжить обычный поток.

Odoo сама ставит зависимую Задачу в состояние `В ожидании`. Дополнительно переводить её во `Внешнее ожидание` не нужно.

## PS-06. Передать работу

При передаче меняется Ответственный.

- следующий Ответственный продолжает сразу → `В работе`;
- работа принята, но продолжится позже → `Очередь`;
- есть внешняя причина ожидания → `Внешнее ожидание`;
- контекст очевиден из Задачи и истории общения → отдельный комментарий не нужен;
- если контекст неочевиден — кратко зафиксировать, что сделано и что осталось.

Если другому человеку нужно выполнить только самостоятельную часть общего результата — использовать Подзадачу, а не передавать всю Задачу.

## PS-07. Составная работа

Использовать:

- **Подзадачу** — для самостоятельной части общего результата;
- **Блокирующую задачу** — для обязательного порядка выполнения;
- **Веху** — для общей контрольной точки нескольких Задач.

Не создавать отдельный Odoo Проект только потому, что работа стала сложной.

## PS-08. Периодическая работа

Для последовательной стабильной периодики включить **Повторяющуюся задачу**.

Штатное поведение Odoo 19:

- предыдущая Задача закрывается состоянием `Готово` или `Отменено`;
- после этого создаётся следующий экземпляр;
- новый экземпляр попадает в первый Этап Проекта;
- его Приоритет сбрасывается на низкий.

Если следующая Задача должна появляться по календарю независимо от закрытия предыдущей, штатная повторяемость для такого сценария не подходит.

## PS-09. Общая контрольная дата

Если несколько Задач должны совместно обеспечить общий результат к дате — связать их с Вехой.

Примеры:

- закрытие периода;
- общий пакет результатов;
- контрольная дата;
- ограниченная по времени инициатива.

Веха не заменяет индивидуальные Крайние сроки Задач.

## PS-10. Личное планирование

Ответственный может дополнительно разложить свои Задачи по Личным этапам:

- `Сегодня`;
- `На этой неделе`;
- `В этом месяце`;
- `Позже`.

Это личный порядок работы. Он не меняет общий Этап `Очередь / В работе / Внешнее ожидание` и не используется руководителем как состояние процесса.

## PS-11. Срок под угрозой

1. Не переносить Крайний срок только потому, что не успеваем.
2. Проверить, изменились ли реальные внешние условия.
3. Если продолжение заблокировано — отразить внешнее ожидание или внутреннюю зависимость.
4. Если нужен выбор между ресурсами, сроками или обязательствами — эскалировать решение.
5. Если оснований для изменения нет — просрочка остаётся видимой.

## PS-12. Проверка результата

Штатные состояния `Требуются изменения` и `Одобрено` используются только там, где конкретный Процесс действительно требует отдельной проверки результата.

Если такой проверки нет, обычная Задача закрывается напрямую состоянием `Готово`.

Не вводить обязательное одобрение каждой Задачи только ради контроля.

## PS-13. Завершить или отменить

### Результат достигнут

Состояние → `Готово`.

### Результат больше не требуется

Состояние → `Отменено`.

Не требуется дополнительно переносить Задачу в отдельную колонку `Готово`.

## PS-14. Вернуть закрытую работу

Если исходный результат оказался неправильным — вернуть ту же Задачу в открытое Состояние и продолжить работу.

Если исходный результат был правильным, а затем появился новый самостоятельный объём — создать новую Задачу и при необходимости сослаться на исходную.

## PS-15. Дубликат

1. Определить основную Задачу.
2. Перенести в неё уникальный контекст.
3. Дубликат перевести в `Отменено`.
4. Историю не удалять.

## PS-16. Работа по письму

Письмо может быть основанием для Задачи, но не каждое письмо должно автоматически становиться Задачей.

Практичный вариант пилота:

- сотрудник получает письмо;
- решает, что появился самостоятельный результат;
- создаёт Задачу или выборочно пересылает письмо на почтовый адрес Проекта;
- дальнейшая переписка и вложения остаются в истории общения Задачи.

## PS-17. Передача смены или рабочего периода

К окончанию рабочего периода Ответственный проверяет незавершённые Задачи:

- продолжает тот же человек позже → ничего специально не создавать;
- работу принимает другой человек → изменить Ответственного;
- есть блокировка → отразить внешнее ожидание или внутреннюю зависимость;
- контекст для следующего Ответственного неочевиден → оставить короткую рабочую заметку.

Отдельный журнал передачи не нужен, если все незавершённые обязательства и их положение уже видны в Odoo.

## PS-18. Найти историю по объекту

Если работа регулярно ищется по человеку, организации, оборудованию или другому объекту:

- использовать структурированное Свойство со ссылкой на подходящую модель Odoo;
- искать и группировать Задачи по этой связи;
- свободный текст оставлять только как дополнение.
