# Контроль

## 1. Кто, когда и что смотрит

| Кто | Когда | Что проверяет | Что делает при отклонении |
|---|---|---|---|
| Исполнитель | постоянно | свои `Очередь`, `В работе`, `Ожидание`, сроки, запросы документов | приводит состояние к факту, сообщает о риске срока, инициирует корректировку параметров |
| Дежурный по входящим | в течение рабочего периода и перед передачей | входящие до контрольного времени | регистрирует работу, обновляет существующую карточку или фиксирует отсутствие действия |
| Старший | ежедневно / по событию | без владельца, передачи, ошибки параметров, риск срока, критичность | исправляет факт, перераспределяет, передаёт вопрос руководителю при управленческом выборе |
| Ответственный за направление | по установленной периодичности | сроки процесса, готовность, регламентные карточки, повторяющиеся ошибки | меняет локальное правило процесса или инициирует изменение процесса |
| Руководитель | по исключениям и на регулярном разборе | критичные, просроченные, старые, перегруз, конфликты ресурсов и сроков | принимает управленческое решение и назначает действие |

Отдельный отчёт не готовится, если данные уже видны в OpenProject.

## 2. Минимальные показатели

| Показатель | Что считаем | Какое решение запускает |
|---|---|---|
| Поступило | новые обязательные карточки за период | рост входа без роста завершения → проверить нагрузку и процесс разбора |
| Завершено | переведённые в `Готово` за период | сравнить с поступлением и динамикой очереди |
| Очередь | текущие карточки в `Очередь` | рост/старение → проверить мощность, приоритеты и сроки |
| В работе | текущие карточки в `В работе` | аномальный рост → проверить фиктивный WIP и распараллеливание |
| Ожидание | карточки в `Ожидание` и их возраст | старение → повторное действие, эскалация или проверка основания ожидания |
| Просрочка | открытые карточки с прошедшим сроком | определить причину, владельца решения и действие; срок не переписывать без основания |
| Запросы | открытые, ожидающие, просроченные | повторное действие / эскалация / проверка владельца |
| Возвраты | карточки, возвращённые из `Готово` из-за ошибки | повторяемость → проверить процесс и качество результата |
| Дубликаты | повторные карточки на один результат | проверить разбор входящего и поиск существующей работы |

Новая метрика добавляется только если по ней принимается решение.

## 3. Ежедневный / сменный контроль

Проверить:

- критичные;
- просроченные;
- без владельца;
- старые в очереди;
- старые в ожидании;
- запросы документов в ожидании и просрочке;
- фактический `В работе`;
- запросы на корректировку параметров;
- неразобранный вход до контрольного времени.

Фиксировать только принятое решение:

```text
Что сделать: <действие>
Кто: <ответственный>
Срок: <дата>
```

## 4. Еженедельный разбор

Смотреть:

- поступило против завершено;
- рост очереди;
- старение очереди и ожидания;
- зависшие запросы документов;
- возвраты и дубли;
- повторяющиеся ошибки регистрации;
- повторяющиеся причины задержек;
- процессы, где локальные правила перестали работать.

Результат — только решения и подтверждённые идеи улучшений.

## 5. Запросы документов

Для каждого открытого `Запроса` должно быть видно:

- что получить;
- кто конкретно сопровождает после отправки;
- когда отправлено;
- срок получения;
- последнее действие.

Обязательные списки:

- `Запросы — ожидаем`;
- `Запросы — просрочено`.

Отправленный запрос не должен оставаться на безличной групповой очереди.

## 6. Групповая очередь

Проверить:

- карточки берутся только при фактическом начале;
- `В работе` всегда имеет реального исполнителя;
- критичные и срочные не остаются невзятыми;
- сотрудники не выбирают системно только удобные карточки.

## 7. Контроль качества

**Обычная выборка** — проверка завершённых работ по установленной периодичности.

**Риск-контроль** — критичные, необычные и подозрительные случаи.

Риск-контроль не используется как показатель общей доли ошибок.

Если найдена ошибка исходного результата — карточка возвращается в работу по PS-13.

## 8. Контроль входящего

Проверять выборку входящих:

- обязательные действия зарегистрированы;
- продолжение не породило лишнюю карточку;
- информационные сообщения не стали задачами;
- неопределённый вход не потерян;
- дубли не создаются системно.

## 9. Контроль регламентов

Ответственный за направление проверяет наличие будущих карточек на установленный горизонт.

Следующий период должен появиться до наступления срока.

## 10. Не использовать как рейтинг сотрудников

- количество закрытых карточек;
- количество комментариев;
- количество смен статуса;
- время в системе;
- количество созданных карточек.

Эти данные можно использовать для поиска перегруза и аномалий, но не как прямой рейтинг производительности.

## 11. Когда рабочий контур настроен плохо

- почти всё находится `В работе`;
- `Ожидание` постоянно растёт;
- запросы документов без владельца, срока или повторного действия;
- сроки массово переносятся перед просрочкой;
- работа остаётся только в почте или чате;
- постоянные карточки без владельца;
- быстро плодятся категории;
- одна карточка живёт месяцами за счёт нового объёма;
- старший стал обязательным согласующим;
- регламентные карточки создаются после наступления срока;
- новый сотрудник не может определить следующий шаг без устного объяснения;
- список идей стал второй обязательной очередью.

## 12. Системный дефект

```text
Что сломано:
<факт>

Почему мешает:
<последствие>

Что меняем:
<действие>

Кто и когда:
<ответственный и срок>
```
