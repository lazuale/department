# Контроль

## 1. Исполнитель

Рабочий список:

- `Очередь`;
- `В работе`;
- `Ожидание`;
- срок;
- критичность.

Для запросов документов — отдельный список `Запросы — ожидаем`.

Отдельный отчёт по своим карточкам не ведётся.

## 2. Старший

Смотрит только исключения:

- нужна корректировка срока, категории, исполнителя, приоритета или постановки;
- работа без владельца;
- передача работы;
- риск срока;
- системные ошибки регистрации.

Старший не проверяет каждую закрытую карточку.

## 3. Руководитель

Контролирует:

- критичные;
- просроченные;
- без владельца;
- старые в очереди;
- старые в ожидании;
- просроченные запросы документов;
- перегруженный `В работе`;
- возвраты после закрытия;
- дубли;
- рост очереди по процессу;
- конфликты сроков, приоритетов и ресурсов.

## 4. Минимальные показатели

| Показатель | Что считаем |
|---|---|
| Поступило | новые обязательные карточки за период |
| Завершено | переведённые в `Готово` за период |
| Очередь | текущие карточки в `Очередь` |
| В работе | текущие карточки в `В работе` |
| Ожидание | текущие карточки в `Ожидание` и их возраст |
| Просрочка | открытые карточки с прошедшим сроком |
| Запросы | открытые, ожидающие, просроченные |
| Возвраты | карточки, возвращённые из `Готово` из-за ошибки |
| Дубликаты | повторные карточки на один результат |

Новая метрика добавляется только если по ней принимается решение.

## 5. Ежедневный / сменный контроль

Проверить:

- критичные;
- просроченные;
- без владельца;
- старые в очереди;
- старые в ожидании;
- запросы документов в ожидании и просрочке;
- фактический `В работе`;
- запросы на корректировку параметров;
- неразобранный вход до контрольного времени.

Фиксировать только принятое решение: что сделать, кто отвечает, срок.

## 6. Запросы документов

Для каждого открытого `Запроса` должно быть видно:

- что получить;
- кто конкретно сопровождает после отправки;
- когда отправлено;
- срок получения;
- последнее действие.

Обязательные списки:

- `Запросы — ожидаем`;
- `Запросы — просрочено`.

Отправленный запрос не должен оставаться на безличной групповой очереди.

## 7. Групповая очередь

Проверить:

- карточки берутся только при фактическом начале;
- `В работе` всегда имеет реального исполнителя;
- критичные и срочные не остаются невзятыми;
- сотрудники не выбирают системно только удобные карточки.

## 8. Еженедельный разбор

Смотреть:

- поступило против завершено;
- рост очереди;
- старение очереди и ожидания;
- зависшие запросы документов;
- возвраты и дубли;
- повторяющиеся ошибки регистрации;
- повторяющиеся причины задержек.

Результат — только решения и подтверждённые идеи улучшений.

## 9. Контроль качества

**Обычная выборка** — небольшая проверка завершённых работ по установленной периодичности.

**Риск-контроль** — критичные, необычные и подозрительные случаи.

Риск-контроль не используется как показатель общей доли ошибок.

## 10. Контроль входящего

Проверять выборку входящих:

- обязательные действия зарегистрированы;
- продолжение не породило лишнюю карточку;
- информационные сообщения не стали задачами;
- неопределённый вход не потерян;
- дубли не создаются системно.

## 11. Контроль регламентов

Ответственный за направление проверяет наличие будущих карточек на установленный горизонт.

Следующий период должен появиться до наступления срока.

## 12. Не использовать как рейтинг сотрудников

- количество закрытых карточек;
- количество комментариев;
- количество смен статуса;
- время в системе;
- количество созданных карточек.

## 13. Красные флаги

- почти всё находится `В работе`;
- `Ожидание` постоянно растёт;
- запросы документов без владельца, срока или повторного действия;
- сроки массово переносятся перед просрочкой;
- работа остаётся только в почте или чате;
- постоянные карточки без владельца;
- быстро плодятся категории;
- одна карточка живёт месяцами за счёт нового объёма;
- старший стал обязательным согласующим;
- список идей стал второй обязательной очередью.

## 14. Системный дефект

```text
Что сломано:
<факт>

Что меняем:
<действие>

Кто и когда:
<ответственный и срок>
```
