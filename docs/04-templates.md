# Шаблоны

Шаблон нужен только там, где свободная форма регулярно создаёт путаницу.

Не нужно дублировать в названии то, что уже хранится отдельным полем.

## 1. Название обычной работы

Формат:

```text
<действие/результат> — <основание или период>
```

Примеры:

- `Обработать основание №123`;
- `Провести сверку — 2026-08`;
- `Подготовить периодический отчёт — 2026-08`;
- `Уточнить содержание обращения — тема X`.

Плохие названия:

- `Срочно`;
- `Посмотреть`;
- `Письмо`;
- `Сделать`;
- `Важно`;
- `RE:`;
- `Работа по файлу`.

## 2. Обычная работа

Обязательный минимум:

```text
Название:
<понятный результат>

Тип:
Работа

Категория:
<устойчивый процесс>

Исполнитель:
<человек или групповая очередь>

Срок:
<внешний срок либо внутренний срок процесса>

Приоритет:
Обычный / Критичный
```

Если внешнего срока нет, автор использует внутреннее правило процесса. Произвольная дата «на глаз» не ставится.

Описание заполняется только если без него нельзя понять результат или ограничения.

Короткий формат:

```text
Основание: <что запустило работу>
Нужно получить: <конечный результат>
Особые условия: <только если есть>
```

Не копировать переписку целиком.

## 3. Запрос важного документа или материала

```text
Название:
Получить <конкретный документ/материал> — <краткая тема>

Тип:
Запрос

Категория:
<процесс, для которого нужен результат>

Исполнитель:
<кто отвечает за получение; после отправки обязательно конкретный человек>

Срок:
<к какой дате результат должен быть получен>

Описание, если нужно:
Нужно получить: <точно что требуется>
Кому направлен запрос: <обобщённо>
Для чего нужен: <кратко, если без этого непонятен смысл>
Связано с: #<ID, если есть>
```

До отправки карточка при необходимости может находиться в групповой очереди. После отправки запрос остаётся открытым за конкретным владельцем до фактического получения результата.

## 4. Комментарий после отправки запроса

```text
Запрос направлен: <дата>.
Ждём: <конкретный документ/материал>.
Адресат: <обобщённо>.
```

Повторное действие:

```text
Повторное действие: <дата>.
Причина: <срок прошёл / ответ неполный / документ не получен>.
Что сделано: <повторный запрос / эскалация / другое>.
```

Новая карточка на каждое напоминание не создаётся.

## 5. Регламентная работа

```text
Название:
<результат> — <период>

Тип:
Регламент

Категория:
<процесс>

Исполнитель:
<человек или группа>

Срок:
<срок этого периода по правилу процесса>
```

Каждый период — отдельная карточка.

## 6. Комментарий при обычном ожидании

```text
Ожидание: <что именно ждём>.
Действие: <что сделано и когда>.
```

Если нужен дополнительный контекст:

```text
После ответа: <следующий шаг>.
```

Плохие комментарии:

- `ждём`;
- `нет ответа`;
- `уточняется`;
- `в процессе`.

## 7. Передача работы

Комментарий нужен только если следующему исполнителю недостаточно самой карточки.

```text
Передача: <что уже сделано>.
Следующий шаг: <одно конкретное действие>.
Риск: <только если есть>.
```

Не переписывать всю историю карточки.

## 8. Корректировка параметров после регистрации

Один формат используется для срока, категории, исполнителя, приоритета и других существенных параметров.

```text
Изменено: <параметр> — <старое значение> → <новое значение>.
Основание: <что фактически изменилось или какая ошибка исправлена>.
```

Примеры:

```text
Изменено: срок — 12.08.2026 → 15.08.2026.
Основание: внешняя сторона подтвердила новый срок предоставления.
```

```text
Изменено: категория — Процесс A → Процесс B.
Основание: при регистрации неверно определён процесс.
```

```text
Изменено: исполнитель — сотрудник A → сотрудник B.
Основание: передача работы следующему исполнителю.
```

Фразы `не успеваем`, `так удобнее`, `поменяли` без понятного основания недостаточны.

Корректировка не используется для замены исходного результата новым.

## 9. Возврат после закрытия

```text
Возврат в работу: <что в первоначальном результате неверно или не завершено>.
Нужно исправить: <конкретно>.
```

Новый дополнительный объём оформляется новой карточкой.

## 10. Отмена

```text
Отменено: <почему сам результат больше не требуется>.
```

Одного слова `неактуально` недостаточно.

## 11. Дубликат

```text
Дубликат работы #<ID>.
Основная карточка: #<ID>.
```

Если во второй карточке есть уникальная полезная информация, сначала перенести её в основную.

## 12. Идея улучшения

```text
Название:
<проблема или улучшение>

Наблюдение:
<что регулярно происходит>

Потеря:
<время, качество, срок, ручной труд, управляемость>

Гипотеза:
<что можно изменить, если уже понятно>

Факты:
<связанные работы или показатели, если есть>

Ожидаемый эффект:
<что должно стать лучше>
```

Идея без готового решения допустима. Идея без понятной проблемы — нет.

## 13. Когда работу можно закрыть

Для каждого устойчивого процесса хранится короткое правило:

```text
Работа считается готовой, если:
- <конечный результат достигнут>;
- <результат сохранён или передан, если это обязательно>;
- открытых обязательных действий больше нет.
```

Для типа `Запрос`:

```text
Запрос считается готовым, если:
- требуемый документ/материал фактически получен;
- результат проверен и соответствует запросу;
- при необходимости сохранён или привязан к связанной работе;
- сопровождение получения больше не требуется.
```

## 14. Карточка реального бизнес-процесса

```text
Название процесса:
<устойчивое название>

Категория:
<значение в OpenProject>

Что запускает:
<условие возникновения работы>

Что является одной работой:
<единица результата>

Когда можно закрыть:
<конечный результат>

Кто обычно выполняет:
<роль или группа>

Как определяется срок:
<внешний срок или внутреннее правило>

Горизонт регламентных работ:
<если процесс периодический>

Когда делить на несколько работ:
<критерий>

Типовые ожидания:
<только реальные повторяющиеся причины>
```

Дополнительные поля добавляются только при реальной необходимости.
