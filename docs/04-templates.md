Шаблоны задают смысл записи. Поля, которые уже есть в Odoo, не дублируются текстом.

## 1. Название Задачи

Формула:

```text
<конечный результат> — <объект / период / основание, если нужно>
```

Хорошо:

- `Сверить данные — <период>`;
- `Исправить запись — <объект>`;
- `Получить подтверждение — <тема>`;
- `Подготовить материал — <период>`.

Плохо:

- `Посмотреть`;
- `Срочно`;
- `Письмо`;
- `Важно`.

## 2. `Работа`

Минимальный набор:

```text
Название: <результат>
Тип задачи: Работа
Процесс: <процесс>
Вид работы: <вид>
Ответственные: <ответственный>
Крайний срок: <срок, если есть>
Приоритет: <штатный уровень Odoo>
```

Дополнительно только по необходимости:

```text
Связанный объект: <сотрудник / контакт / оборудование / другой объект>
Описание: <контекст, без которого нельзя понять результат>
```

## 3. `Запрос`

```text
Название: Получить <что> — <тема>
Тип задачи: Запрос
Процесс: <процесс>
Ответственные: <ответственный>
Крайний срок: <срок получения>
```

После отправки, если остаётся только ждать:

- Этап `Внешнее ожидание`;
- Активность на дату следующего контроля, если она нужна;
- переписка и вложения — в истории общения Задачи.

## 4. Внешнее ожидание

Не переписывать штатные поля в комментарий.

Комментарий нужен только для контекста, например:

```text
Ожидается: <конкретный результат>
Что уже сделано: <только если это не видно из истории>
```

Если известно, когда вернуться к вопросу — ставится Активность.

## 5. Передача

Комментарий не обязателен, если следующему Ответственному всё понятно из Задачи.

Если нужен контекст:

```text
Сделано: <кратко>
Осталось: <кратко>
Риск / ограничение: <если есть>
```

## 6. Проверка результата

Если конкретный Процесс действительно требует отдельной проверки:

```text
Состояние: Одобрено
```

или

```text
Состояние: Требуются изменения
Комментарий: <что именно нужно исправить, если это не очевидно>
```

Не использовать этот цикл для каждой обычной Задачи.

## 7. Описание Процесса

Процесс описывается по форме из [05 — Описание процессов](05-processes.md).
