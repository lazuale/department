## 1. Название работы

```text
<результат> — <основание или период>
```

Примеры:

- `Обработать основание №123`;
- `Провести сверку — 2026-08`;
- `Получить документ — тема X`.

Не использовать: `Срочно`, `Посмотреть`, `Письмо`, `Важно`, `RE:`.

## 2. Обычная работа

```text
Название: <понятный результат>
Тип: Работа
Категория: <процесс>
Исполнитель: <человек или группа>
Срок: <внешний или внутренний срок процесса>
Приоритет: Обычный / Критичный
```

Описание — только если без него непонятен результат:

```text
Основание: <что запустило работу>
Нужно получить: <результат>
Особые условия: <если есть>
```

## 3. Запрос документа или материала

Использовать только если получение соответствует критериям раздела 13 [модели управления](01-methodology.md#13-запрос-документа-или-материала).

```text
Название: Получить <документ/материал> — <тема>
Тип: Запрос
Категория: <процесс>
Исполнитель: <после отправки — конкретный человек>
Срок: <дата получения>

Нужно получить: <точно что>
Кому направлен запрос: <обобщённо>
Связано с: #<ID, если есть>
```

После отправки карточка остаётся открытой до получения и проверки результата.

## 4. Отправка и повторное действие по запросу

```text
Запрос направлен: <дата>.
Ждём: <что>.
Адресат: <обобщённо>.
```

```text
Повторное действие: <дата>.
Причина: <просрочка / неполный ответ / документ не получен>.
Что сделано: <действие>.
```

## 5. Регламентная работа

```text
Название: <результат> — <период>
Тип: Регламент
Категория: <процесс>
Исполнитель: <человек или группа>
Срок: <по правилу процесса>
```

## 6. Ожидание

```text
Ожидание: <что ждём>.
Действие: <что сделано и когда>.
После ответа: <следующий шаг, если нужен>.
```

Не писать только `ждём`, `нет ответа`, `уточняется`, `в процессе`.

## 7. Передача

```text
Передача: <что сделано>.
Следующий шаг: <конкретное действие>.
Риск: <если есть>.
```

Комментарий нужен только если карточки недостаточно для продолжения.

## 8. Корректировка параметра

```text
Изменено: <параметр> — <старое> → <новое>.
Основание: <ошибка или изменившийся факт>.
```

Пример:

```text
Изменено: срок — 12.08.2026 → 15.08.2026.
Основание: подтверждён новый срок предоставления.
```

`Не успеваем` и `так удобнее` не являются основанием.

## 9. Возврат после закрытия

```text
Возврат в работу: <ошибка исходного результата>.
Нужно исправить: <что именно>.
```

Новый объём = новая карточка.

## 10. Отмена

```text
Отменено: <почему результат больше не нужен>.
```

## 11. Дубликат

```text
Дубликат работы #<ID>.
Основная карточка: #<ID>.
```

Уникальную информацию сначала перенести в основную карточку.

## 12. Идея улучшения

```text
Название: <проблема или улучшение>
Наблюдение: <что повторяется>
Потеря: <время / качество / срок / ручной труд>
Гипотеза: <что изменить, если понятно>
Факты: <связанные карточки или показатели>
Ожидаемый эффект: <что должно улучшиться>
```

## 13. Когда можно закрыть

Обычная работа:

```text
- конечный результат достигнут;
- результат сохранён или передан, если это требуется;
- открытых обязательных действий нет.
```

`Запрос`:

```text
- документ/материал получен;
- результат проверен и подходит;
- при необходимости сохранён или привязан;
- сопровождение больше не требуется.
```

## 14. Карточка процесса

```text
Название: <процесс>
Зачем существует: <какую обязательную функцию закрывает>
Категория: <значение в OpenProject>
Что запускает: <условие>
Одна работа: <единица результата>
Когда закрывать: <конечный результат>
Кто выполняет: <роль или группа>
Срок: <внешний или внутреннее правило>
Горизонт регламентов: <если нужен>
Когда делить: <критерий>
Допустимые ожидания: <если есть повторяющиеся внешние причины>
Исключения: <только реальные особенности процесса>
```

## 15. Локальные правила направления

Использовать одну карточку/страницу для фиксированных значений направления:

```text
Направление: <название>
Ответственный за направление: <роль/сотрудник>

Контрольное время разбора входящих:
<время или правило>

Внутренние сроки:
<процесс 1> — <срок>
<процесс 2> — <срок>

Горизонт создания регламентных работ:
<процесс / период>

Выборочный контроль качества:
<периодичность и объём, если установлен>

Дата последнего изменения:
<дата>
```

Локальное значение задаётся один раз и применяется одинаково ко всем работам соответствующего процесса.
