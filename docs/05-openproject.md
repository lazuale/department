# Рабочий контур OpenProject Community

## 1. Постоянные проекты

```text
Работа подразделения
Развитие и автоматизация
```

В `Работа подразделения`:

- `Работа`;
- `Запрос`;
- `Регламент`;
- разовые поручения.

Отдельный проект — только когда одной карточки или иерархии недостаточно.

## 2. Типы

| Тип | Для чего |
|---|---|
| `Работа` | обычный обязательный результат |
| `Запрос` | получить важный документ/материал и довести получение до результата |
| `Регламент` | периодическая работа |
| `Идея` | улучшение в отдельном проекте развития |

## 3. Состояния

```text
Очередь
В работе
Ожидание
Готово
Отменено
```

Основной путь:

```text
Очередь → В работе → Готово
              ↕
          Ожидание
```

Для `Запроса`:

```text
Очередь → В работе → Ожидание → В работе → Готово
```

`Ожидание → Готово` не используется.

## 4. Приоритет

Использовать только:

- `Обычный`;
- `Критичный`.

Порядок внутри каждого уровня: ближайший срок → более старая карточка.

## 5. Категории

Категория = устойчивый бизнес-процесс.

Не использовать категории для:

- статуса;
- срочности;
- сотрудника;
- отдельного документа;
- временной темы.

Каждой категории должна соответствовать карточка процесса.

## 6. Исполнитель и групповая очередь

Открытая карточка имеет конкретного исполнителя или контролируемую группу.

Из групповой очереди сотрудник назначает себя только при фактическом начале.

Передачу уже назначенной карточки делает старший.

Для `Запроса` после отправки обязательно остаётся конкретный владелец.

## 7. Поля карточки

Минимум:

- название;
- тип;
- категория;
- состояние;
- исполнитель или группа;
- срок;
- приоритет;
- описание и вложения — при необходимости.

После создания параметры меняются по правилам [основного регламента](01-methodology.md).

## 8. Доска

```text
Очередь | В работе | Ожидание | Готово
```

`Отменено` можно скрыть из ежедневной доски.

## 9. Списки исполнителя

`Моя работа`:

- только открытые;
- исполнитель = текущий пользователь или его группа;
- колонки: ID, название, тип, категория, состояние, приоритет, срок.

Сортировка:

1. критичные — ближайший срок → старые;
2. обычные — ближайший срок → старые.

`Запросы — ожидаем`:

- тип = `Запрос`;
- состояние = `Ожидание`;
- исполнитель = текущий пользователь;
- ближайшие сроки сверху.

## 10. Контрольные списки

- `Вся активная работа`;
- `Просрочено`;
- `Без исполнителя`;
- `Критичные`;
- `Старые в очереди`;
- `Старые в ожидании`;
- `Запросы — ожидаем`;
- `Запросы — просрочено`;
- `По категориям`;
- `По исполнителям`;
- `Готово за период`.

Неиспользуемые списки удаляются.

## 11. Регламенты

Каждый период — отдельная карточка типа `Регламент`.

Будущие карточки создаются на горизонт, установленный для процесса.

## 12. Родительские, дочерние и связанные карточки

Дочерние карточки — только для независимо контролируемых частей.

Связи используются для:

- нового объёма после предыдущей работы;
- запроса документа, связанного с другой работой;
- идеи и её реализации;
- дубликатов.

Закрытие дочерних карточек не закрывает родительскую автоматически.

## 13. Развитие и автоматизация

```text
Входящие идеи → Наблюдаем → Кандидат → Готово к решению
```

После решения `делаем` создаётся обязательная работа: одна карточка, иерархия или отдельный проект.

## 14. Разграничение действий

- автор задаёт параметры при создании;
- исполнитель ведёт состояние;
- старший исправляет параметры по основанию;
- руководитель принимает управленческие решения;
- старший не согласует обычное закрытие.

Техническая матрица прав в этот регламент не входит.

## 15. Не добавлять без необходимости

- новые статусы;
- новые типы;
- десятки категорий;
- обязательные согласования;
- отдельный проект на каждую функцию;
- отдельный отчёт поверх данных OpenProject;
- обязательные поля без применения;
- `Запрос` на каждое уточняющее письмо.
