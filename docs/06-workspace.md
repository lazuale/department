Правила работы определены в [модели управления](01-methodology.md). Здесь фиксируется только состав рабочего контура.

## 1. Структура

Рабочий контур содержит обязательства. Если в нём фиксируются `Идеи`, они существуют до решения руководителя, но не образуют отдельный контур или доску. После решения `делаем` создаётся связанное обязательство.

Отдельный проект создаётся для самостоятельного контура с несколькими результатами, участниками, этапами и зависимостями.

## 2. Минимальная конфигурация

| Типы обязательств | Состояния |
|---|---|
| `Работа`, `Запрос` | `Очередь`, `В работе`, `Ожидание`, `Готово`, `Отменено` |

Если идеи фиксируются в рабочем контуре, используется отдельный необязательный тип записи `Идея`. Он не относится к типам обязательств и не требует отдельного набора состояний.

Для обязательств дополнительно используются:

| Элемент | Настройка |
|---|---|
| Приоритеты | `Обычный`, `Критичный` |
| Исполнитель | конкретный сотрудник |
| Групповая очередь | рабочая группа |
| Связи | связанные и блокирующие карточки; родительская/дочерняя структура |

Категории добавляются только при необходимости для фильтрации, группировки или анализа.

Переходы состояний и доступные действия настраиваются по рабочим ролям.

## 3. Групповые очереди

Для каждой групповой очереди фиксируется один режим:

- самоназначение;
- контролируемое назначение старшим.

## 4. Рабочая доска

Колонки: `Очередь` | `В работе` | `Ожидание` | `Готово`.

`Отменено` в ежедневный вид можно не выводить.

## 5. Рабочие представления

Минимальный набор:

- `Моя работа`;
- `Вся активная работа`;
- `Просрочено`;
- `Ожидание`;
- `Запросы`.

Для `Моя работа` применяется порядок очереди из [раздела 7 модели](01-methodology.md#7-порядок-очереди-и-критичность).

Остальные контрольные признаки из [раздела 3 контроля](03-control.md#3-оперативный-контроль) используются как фильтры при необходимости.

## 6. Периодические работы

Для процессов с периодической работой задаётся горизонт будущих карточек.

## 7. Описание процессов

Процессы сначала описываются по форме из [05 — Описание процессов](05-processes.md), затем отражаются в рабочем контуре.

## 8. Проверка перед запуском

- [ ] если используются отдельные проекты — определены их границы;
- [ ] описаны процессы;
- [ ] настроены типы, состояния и приоритеты;
- [ ] проверены переходы состояний для рабочих ролей;
- [ ] если используются категории — определено их назначение;
- [ ] определены сотрудники; если используются групповые очереди — определены рабочие группы;
- [ ] если используются групповые очереди — для каждой выбран режим назначения;
- [ ] настроены рабочая доска и представления;
- [ ] если у процесса нет внешнего срока — определён внутренний срок;
- [ ] если есть периодические работы — задан горизонт будущих карточек;
- [ ] проверены обычная работа, ожидание, внутренняя зависимость, запрос, передача и возврат;
- [ ] если есть периодические работы — проверен сценарий периодической работы.
